## Bugs found and fixed

1. **Payment webhook could be blocked by a forged request (security).** A webhook with a bad signature was stored first and took the event id, so the genuine event with that id was then ignored as a duplicate: the citizen paid but the bill stayed open. Forged events are now kept for audit without claiming the id (migration 0029, new test).
2. **Stripe signature check failed during secret rotation.** Stripe sends several `v1` signatures while a secret is rolled; only the last one was checked. Now any valid one is accepted.
3. **Stripe delayed payments.** `checkout.session.completed` with `unpaid` was treated as a failure; `async_payment_succeeded` was ignored. Both are handled now.
4. **WaafiPay approval assumed on a missing state.** A response with code 2001 and no state counted as approved. Only an explicit `APPROVED` counts now.
5. **Unknown addresses sent visitors to the sign-in page** and showed an unstyled 404. They now show the branded, translated "Page not found" with a 404 status.
6. **The `/design` component gallery was public in production.** It now exists in development only (or with `DESIGN_GALLERY=1`).
7. **Assistant page crashed** in newer browsers (an effect returned the Promise from `scrollIntoView`). Fixed earlier in this round.

## Payments: what works and what needs accounts

- **Mobile money (EVC Plus, Zaad, Sahal, eDahab)** goes through WaafiPay, which serves all four wallets. The pay form now says which wallet will get the prompt (from the number's prefix). Needs `WAAFIPAY_MERCHANT_UID`, `WAAFIPAY_API_USER_ID`, `WAAFIPAY_API_KEY` and `WAAFIPAY_WEBHOOK_SECRET` from a WaafiPay merchant account.
- **Cards (Stripe Checkout)** are built and unit-tested. Needs `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`. Stripe doesn't open accounts in Somalia; the administration needs an entity or partner in a supported country (open question 3).
- **Checkout flow verified** with the development test provider: intent → decline shown with reason → retry → approved → payment ONL-2026-000003 recorded, invoice paid, both webhooks signature-checked, SMS receipt queued, ledger balanced. The test provider is switched off again.

## Not verified in this audit

- **Staff and admin screens in a browser while signed in.** Those need a real staff sign-in with 2FA, which only the account owner can do. The pages build, are guarded, and their database functions are tested.
- **Live WaafiPay and Stripe payments**, until merchant and test keys are configured.
- **Real SMS delivery**, until `SMS_PROVIDER` is set.
